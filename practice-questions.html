1

Secure development: vulnerabilities, risks and controls

~14 marks per paper U4 AoS 2
Key knowledge assessed
  • Types of vulnerabilities and risks within insecure development environments
  • Security controls used to protect software development practices and data stored within applications
  • Threat modelling principles — defining security requirements, identifying and mitigating threats, confirming threats have been mitigated
  • Strategies for improving the security of software development practices — onboarding and developer training, risk management plans

This is the single largest block of marks on the paper, and the one where generic answers are punished hardest. The examiners consistently refuse security controls offered as risk-management strategies, and refuse backup and archiving as security measures. Students must be able to say which of the two lists a term belongs to.

Q1.1U4 AoS 2AchievableSection B style · new3 marks

A software development organisation runs a single combined development, testing and production environment. Describe one risk this creates for the organisation and suggest one security control that would reduce it.

6 ruled lines
Show response
Full-mark response

Risk: Because development, testing and production share one environment, code that has not been fully tested runs against live data. Bugs and vulnerabilities introduced while developing are exposed to real users immediately, which can cause system downtime or allow an attacker to exploit the application before the fault is found.

Control: Separate the development, testing and production environments, so that changes are written and verified in development and testing and only released to production once they pass testing.

Marking
  • 1States the risk — untested or in-progress code runs in the live environment.
  • 1States a consequence for the organisation — downtime, data loss, or an exploitable vulnerability reaching users.
  • 1Names a valid security control from the study design that addresses that risk.
Minimum full-mark answer

Risk: untested code runs on the live system, so errors and vulnerabilities reach real users and can be exploited. Control: separate the development, testing and production environments.

Q1.2U4 AoS 2HardSection C style · new4 marks

Following a security review, a development company can fund only one improvement this year: developer training focused on secure coding, or robust identity and access management. Justify which improvement the company should implement first.

8 ruled lines
Show response
Full-mark response

Improvement: Developer training focused on secure coding.

Training addresses the cause rather than the symptom. The review found vulnerabilities written into the code itself, and developers who understand secure coding practices stop those vulnerabilities being created in the first place, across every project the company runs.

Robust identity and access management only restricts who can reach the code and data; it would not prevent an authorised developer from writing insecure code, so the same vulnerabilities would continue to be introduced. It is also a control the company can layer on later once the development practice itself is sound.

Marking
  • 1Clearly states the chosen option.
  • 1Explains why the chosen option is suitable.
  • 1Explains why the alternative is less suitable — the mark most often lost.
  • 1Applies the argument to the organisation in the scenario.
Minimum full-mark answer

Developer training. Training stops vulnerabilities being written into the code at all, so it fixes the cause of the problems the review found. Identity and access management only limits who can reach the code — an authorised developer would still write the same insecure code, so the vulnerabilities would keep appearing.

Testing and debugging

~11 marks per paper U3 AoS 1 · U4 AoS 1
Key knowledge assessed
  • Debugging and testing techniques — breakpoints, debugging statements, commenting out code, construction of relevant test data
  • Test cases comparing expected and actual output in testing tables
  • Strategies for conducting beta testing — testing plan and test scenarios, observation, documentation of results
  • Types of errors — syntax, logic, runtime (overflow, index out of range, type mismatch, divide by zero)

A test table appears in some form on every paper, and it is the most mechanical set of marks available. The recurring failure is coverage: students test one value instead of testing above, on and below each boundary, and they abbreviate the expected output instead of writing exactly what the algorithm prints.

Q2.2U4 AoS 1HardAdapted from 2025 C Q12b3 marks

Alpha testing of a council's bin-collection reminder app is complete. Describe a beta testing strategy the developer could implement with residents.

6 ruled lines
Show response
Full-mark response

Residents would be selected to represent the range of real users — for example, a random sample drawn from each suburb in the council area, including some residents who have not used the app before.

A test scenario would be written for each core feature, such as "set a reminder for a green-waste collection and confirm the notification arrives the evening before", and testers would work through the scenarios on their own devices.

Results would be documented as the tests are observed — the time taken for each step, any step the tester could not complete, and comments the tester makes — so the developer can recommend modifications to the app.

Marking
  • 1How the testers are selected, in the context of the scenario.
  • 1What will be tested — a described test scenario, not just "they test the app".
  • 1What data will be collected and how it is documented.
Minimum full-mark answer

Randomly select residents from across the council area. Give them a scenario to complete, such as setting a reminder for a green-waste collection. Observe and record how long each step takes and any step they cannot complete.

Marks are not awarded for describing functional testing of outputs, or for "bug testing" — beta testing is about real users working through scenarios.

Data types, data structures and data sources

~8 marks per paper U3 AoS 1
Key knowledge assessed
  • Data types — character, string, integer, floating point, date/time, Boolean
  • Data structures — one-dimensional arrays, two-dimensional arrays, records (varying data types, field index)
  • Data sources — plain text (TXT), delimited (CSV) and XML: structure and reasons for use

Reliable marks, reliably lost on terminology. "Bool" and "Float" earn nothing where the study design says Boolean and floating point, and a reason given for XML must be a structural reason — extensibility, self-describing tags, hierarchy, interoperability — not speed, size or security, all of which the reports have explicitly refused.

A vet clinic's booking module stores, for each appointment: the pet's name, the owner's mobile number, whether the owner has confirmed attendance, and the consultation fee.

State the most appropriate data type for each item, and justify your choice for the mobile number.

Pet's name — string. Owner's mobile number — string. Confirmed attendance — Boolean. Consultation fee — floating point.

The mobile number is stored as a string because it begins with a leading zero, which a numeric data type would discard, and because no arithmetic is ever performed on it.

  • 1Consultation fee as floating point.
  • 1Mobile number as string.

Q3.2U3 AoS 1HardSection C style · new4 marks

A school timetabling system must send each student's weekly timetable to a third-party parent portal. A junior developer suggests a CSV file; the team leader prefers XML. Justify which data source the team should use.

8 ruled lines
Show response
Full-mark response

Data source: XML.

A timetable is hierarchical — each student has many days, and each day has a varying number of classes. XML represents that structure directly through nested, user-defined tags, so each value also carries a name describing what it is. That makes the file interoperable: the parent portal can interpret the data without a separate specification, and the structure can be extended later if the school adds, for example, a room number.

A CSV file separates values with a delimiter and assumes a fixed number of fields in a fixed order. With a varying number of classes per day the record length would change, and the portal would need extra documentation to know what each column means — any change to the fields would break it.

Marking
  • 1States XML as the choice.
  • 1A correct structural statement about XML — tags, hierarchy, extensibility or interoperability.
  • 1A correct structural statement about CSV — delimiters, fixed fields, no embedded description.
  • 1Links the comparison to the varying number of classes in the scenario.
Minimum full-mark answer

XML. Its user-defined tags describe each value and can nest, so a student with a different number of classes each day still fits, and the portal can interpret it without extra documentation. CSV only separates values with commas in a fixed order, so a varying number of classes would break the column layout.

Reports have specifically refused "XML is faster", "XML is smaller" and "XML is more secure" as incorrect statements.

Q4.2U3 AoS 1AchievableSection B style · new2 marks

Compare a function with a method.

4 ruled lines
Show response
Full-mark response

A function is a named block of code that performs a task and returns a value, and it can be called by name from anywhere in the program. A method is a block of code that belongs to a class, so it can only be called through an object of that class.

Marking
  • 1A correct account of a function — returns a value, called by name.
  • 1A correct account of a method — belongs to a class, called through an object — with the difference made explicit.
Minimum full-mark answer

A function is called by name from anywhere in the program and returns a value, whereas a method belongs to a class and can only be called through an object of that class.

In 2023 Section C Q11a, 59% of students scored zero asking essentially this. Most could define one of the two and then had nothing to compare it against.

Q4.3U3 AoS 1HardSection C style · new4 marks

A delivery app holds 20 000 parcel records sorted by tracking number. A developer must choose between a binary search and a linear search to find a record by its tracking number. Justify which algorithm should be used.

8 ruled lines
Show response
Full-mark response

Algorithm: Binary search.

The records are already sorted by tracking number, which is the field being searched, and a sorted list is what a binary search requires. It discards half the remaining records at each step, so a match among 20 000 records is found in roughly 15 comparisons.

A linear search would also return the correct record, but it checks each record in turn from one end of the list, so a record near the end would take up to 20 000 comparisons. With the list already sorted on the search field there is no reason to accept that cost.

Marking
  • 1States binary search.
  • 1States why it is suitable — the list is sorted on the field being searched.
  • 1States the efficiency gain — halving the list, far fewer comparisons.
  • 1States why a linear search is less suitable here.
Minimum full-mark answer

Binary search. The records are already sorted by tracking number, which is what a binary search needs, and it halves the list at each step so it finds a record in about 15 comparisons. A linear search would still work but checks every record in turn, so it could make 20 000 comparisons.

2024 Section C Q6 asked the mirror image of this, where a linear search was correct because the records were sorted by a different field from the one being searched. Read which field the list is sorted on before choosing.

Q4.4U4 AoS 1AchievableSection C style · new3 marks

In a banking application, the balance attribute of the Account class is declared private, and is changed only through a deposit() method. Explain why the attribute is declared private rather than public.

6 ruled lines
Show response
Full-mark response

Declaring balance private means no code outside the Account class can read or write it directly. Every change has to pass through deposit(), which can validate the amount before applying it — rejecting a negative figure, for example.

As a result the balance cannot be set to an invalid value by another part of the program, and the way it is stored internally can be changed later without breaking any code elsewhere, because the rest of the program depends only on the method.

Marking
  • 1Private restricts access to code within the class.
  • 1Changes must go through the method, which can validate them.
  • 1A consequence — the attribute cannot reach an invalid state, or the implementation can change without affecting other code.
Minimum full-mark answer

Private means no code outside the Account class can change balance directly. Every change must go through deposit(), which can check the amount is valid first, so the balance can never be set to an invalid value from elsewhere in the program.

Access modifiers are new in the study design from 2025 and have not been examined in any paper from 2020 to 2025.

Analytical tools — context diagrams, DFDs, use case diagrams

~7 marks per paper U3 AoS 2
Key knowledge assessed
  • Context diagrams (Level 0) — components of a system, entities and data flows
  • Data flow diagrams (Level 1) — processes, entities, data stores and data flows
  • Use case diagrams — system boundary, actors, associations, relationships (includes and extends), use cases

Nearly always a labelling or error-spotting question. Two rules carry most of the marks: an external entity may never connect directly to a data store, and the arrow direction differs between <<includes>> and <<extends>>. Students also lose marks for dropping underscores from data flow names copied out of the insert.

Q5.1U3 AoS 2AchievableAdapted from 2025 C Q4b2 marks

In a Level 1 data flow diagram, a data flow named payment_details runs directly from the Customer external entity to the Accounts data store. Identify and explain the error.

4 ruled lines
Show response
Full-mark response

The error is that the payment_details data flow connects the Customer external entity directly to the Accounts data store. In a data flow diagram, data moving between an external entity and a data store must pass through a process, so the flow should go from Customer to a process, which then writes to Accounts.

Marking
  • 1Identifies the specific flow and the two components it wrongly connects.
  • 1Explains the convention — an external entity cannot connect directly to a data store; a process must sit between them.
Minimum full-mark answer

The payment_details flow goes straight from the Customer entity to the Accounts data store. An external entity cannot send data directly to a data store — it must go through a process first.

Log in: includes — it always happens as part of booking. Add to calendar: extends — it is optional and booking is complete without it.

Q6.2U3 AoS 1AchievableSection B style · new3 marks

A developer has produced a mock-up of a solution's main screen. Explain why an object description and pseudocode are also required, with reference to what each one represents.

6 ruled lines
Show response
Full-mark response

A mock-up represents only the appearance of the user interface — the layout, controls and labels the user sees. It says nothing about how the solution is structured or how it behaves.

An object description sets out the structure: the properties and attributes of each object, their data types, and the methods belonging to it. Pseudocode represents the functionality: the logic of each algorithm, step by step, in a language-independent form. Together the three tools cover the appearance, structure and functionality of the design.

Marking
  • 1States what a mock-up represents, and that it covers appearance only.
  • 1States what an object description represents — properties/attributes and methods.
  • 1States what pseudocode represents — the logic of an algorithm.
Minimum full-mark answer

A mock-up only shows the appearance of the interface. An object description shows the structure — the properties, attributes and methods of each object. Pseudocode shows the functionality — the logic of the algorithm.

File management

~6 marks per paper U3 AoS 2
Key knowledge assessed
  • Naming conventions — Hungarian notation, camel casing, snake casing
  • Version control · backups (full, incremental, differential) · security · disposal

The distinction that earns marks here is version control versus backup: one tracks changes so a previous version can be restored, the other keeps a separate copy so a lost or corrupted file can be recovered. Students who treat them as the same thing cannot answer either question.

Q7.1U3 AoS 2EasyAdapted from 2023 B Q62 marks

Compare version control with backing up a file.

4 ruled lines
Show response
Full-mark response

Version control keeps a record of the successive changes made to a file so that the developer can see what changed, when, and by whom, and can roll the file back to an earlier working version. Backing up instead stores a separate copy of the file at a point in time, so that the file can be restored if the original is lost, corrupted or deleted.

Marking
  • 1Correct account of version control — tracked changes, roll back to a previous version.
  • 1Correct account of backup — separate copy, restored after loss or corruption.
Minimum full-mark answer

Version control records every change to a file so an earlier version can be restored. A backup is a separate copy of the file kept so it can be recovered if the original is lost or corrupted.

Q7.2U3 AoS 2AchievableSection B style · new3 marks

A development team backs up its work to an external drive every night and keeps every backup indefinitely. Suggest a backup scheme the team should use instead, and outline one benefit of your suggestion.

6 ruled lines
Show response
Full-mark response

The team should run a full backup once a week and incremental backups on each of the other nights, storing one copy off-site or in the cloud in addition to the external drive, and setting a retention period after which old backups are disposed of securely.

Incremental backups copy only the files that have changed since the previous backup, so each nightly run finishes far more quickly and uses much less storage than a full copy every night.

Marking
  • 1Names a backup type combination — full plus incremental or differential.
  • 1Addresses where backups are stored, or how long they are kept.
  • 1States a benefit — reduced time or storage, or faster recovery.
Minimum full-mark answer

A weekly full backup with incremental backups on the other nights, with one copy kept off-site. Incremental backups only copy files that have changed, so each run is much faster and uses less storage.

Project management

~5–6 marks per paper U3 AoS 2 · U4 AoS 1
Key knowledge assessed
  • Gantt charts — identification and sequencing of tasks, time allocation, dependencies, milestones, critical path
  • Monitoring and documenting the progress of projects
  • Techniques for recording progress — adjustments to tasks and time frames, annotations, logs and journals
  • Techniques for assessing the effectiveness of a project plan; factors that affect it — scope creep, personnel changes, technical issues

Reliably the opening question of Section B. Students lose marks by describing what a Gantt chart is instead of how it is used, and by naming any task as a milestone — a milestone is a point of zero duration marking the completion of a stage.

Q8.1U4 AoS 1AchievableAdapted from 2025 B Q13 marks

A developer is managing a six-month project using a Gantt chart. Explain how the chart can be used to monitor and document the progress of the project.

6 ruled lines
Show response
Full-mark response

As each task is worked on, its actual start and finish dates are recorded against the planned duration shown on the chart, so the developer can see at a glance whether a task is ahead of or behind schedule.

Because the chart shows dependencies, a task that runs over can be traced forward to the tasks that cannot start until it finishes, and the developer can tell whether the delay falls on the critical path and will therefore push out the whole project.

Annotations are added to record the adjustments made to tasks and time frames and the reason for each, which documents how the project actually progressed.

Marking
  • 1Comparing actual progress against the planned duration.
  • 1Using dependencies or the critical path to judge the impact of a delay.
  • 1Documenting the change — annotations, adjusted time frames, or a log.
Minimum full-mark answer

Record each task's actual progress against its planned duration to see if it is behind schedule. Follow the dependencies to check whether a late task is on the critical path and will delay the whole project. Annotate the chart with the changes made and why.

Q8.2U4 AoS 1EasySection C style · new2 marks

At the end of the project the developer reviews the project plan. Outline two techniques for assessing how effective the plan was.

4 ruled lines
Show response
Full-mark response

Count the number of changes made to the project plan over the course of the project and examine the reason each change was necessary — a plan that needed constant revision was not an accurate forecast.

Assess the impact those changes had on the completion of the project, for example whether milestones were still met on their original dates.

Marking
  • 1Reviewing the number of changes made and why they were needed.
  • 1Assessing the impact of those changes on project completion.
Minimum full-mark answer

Review how many changes were made to the plan and why. Assess what impact those changes had on completing the project on time.

Q8.3U4 AoS 1HardSection C style · new3 marks

Midway through development, the client asked for two features that were not in the original requirements, and one of the two developers left the company. The project finished five weeks late.

Discuss how these events affected the effectiveness of the project plan.

6 ruled lines
Show response
Full-mark response

The additional features are scope creep. Tasks that were never in the plan had to be inserted mid-project, so the original time allocations and the critical path no longer reflected the work actually required, and the plan stopped being a reliable forecast of the finish date.

The personnel change compounded this: the remaining developer absorbed tasks the plan had allocated to two people, so durations that were realistic for a two-person team became unachievable without being re-estimated.

The plan was therefore ineffective as a predictive tool, though it still had value — the number of changes recorded against it and the reasons for them explain the five-week overrun and can inform the estimates on the next project.

Marking
  • 1Names scope creep and its effect on tasks, durations or the critical path.
  • 1Names the personnel change and its effect on task allocation or duration.
  • 1Reaches a position on how effective the plan was, referring to the five-week overrun.
Minimum full-mark answer

The extra features are scope creep — new tasks were added that the plan never allowed time for, so the durations and critical path were wrong. Losing a developer meant one person did work planned for two, so those durations became unachievable. The plan was not an effective forecast, which is why the project ran five weeks late.

Evaluation criteria, efficiency and effectiveness

~5–6 marks per paper U3 AoS 2 · U4 AoS 1
Key knowledge assessed
  • Criteria for evaluating design ideas and the efficiency and effectiveness of solutions
  • Features of evaluation strategies — evaluation criteria, time frame, responsibility, techniques for applying criteria
  • Characteristics of efficient and effective solutions — user-centred design, clear and concise code, detailed internal documentation

The recurring failure is unmeasurable criteria. "The solution is easy to use" cannot be applied; "Can a new user complete a booking in under two minutes without assistance?" can. Students also confuse the two words: efficiency is about time, cost and effort; effectiveness is about whether the solution does what it is supposed to. Usability is a measure of effectiveness.

Q9.1U4 AoS 1HardSection C style · new3 marks

A developer is preparing to evaluate a completed stocktake app. Suggest three criteria that could be used to evaluate the efficiency and effectiveness of the solution. At least one criterion must address efficiency and at least one must address effectiveness.

Three answer lines
Show response
Full-mark response

Efficiency: Can a staff member record a stocktake count for one aisle in under five minutes?

Effectiveness: Does the app produce a stocktake report containing every required field — item code, counted quantity, system quantity and variance?

Effectiveness: Can staff complete a count without assistance after a single training session?

Marking
  • 1A measurable efficiency criterion — time, steps, or cost.
  • 1A measurable effectiveness criterion — completeness, accuracy, or whether a requirement is met.
  • 1A third distinct, measurable criterion, not a restatement of the first two.
Minimum full-mark answer

Can a staff member count one aisle in under five minutes? (efficiency) Does the report include item code, counted quantity, system quantity and variance? (effectiveness) Can a new staff member complete a count unassisted after one training session? (effectiveness)

Each criterion must be measurable or posed as a question. General statements such as "the app is user-friendly" are not awarded.

Time frame: A point far enough after implementation for real usage data to exist — typically three to six months after the app goes live, so a full stocktake cycle has been completed using it.

Requirements, constraints, scope and the SRS

~5 marks per paper U3 AoS 2
Key knowledge assessed
  • Characteristics of functional and non-functional requirements
  • Constraints — economic, legal, social, technical considerations
  • Characteristics of solution scope — version and solution boundaries
  • Purpose and features of a software requirements specification

Almost always a classification table. The trap is category confusion — usability offered where the constraint is technical, social offered where it is legal — and mixing taxonomies by classifying a constraint as a functional requirement. Work from the study design's categories, not everyday meaning.

Q10.2U3 AoS 2AchievableSection B style · new3 marks

A netball club wants an app to manage team selections. Describe how an economic, a legal and a technical constraint could each influence the development of this solution.

Economic: A volunteer-run club has a small budget, so the developer may not be able to pay for cloud hosting or paid libraries, limiting the features that can be built.

~4 marks per paper U3 AoS 2 · U4 AoS 2
Key knowledge assessed
  • Copyright Act 1968 (Cwlth) · Privacy Act 1988 (Cwlth), APP 1, 3, 6, 8, 9, 11 · Privacy and Data Protection Act 2014 (Vic), IPP 1, 2, 4, 5, 7, 9, 10

Q11.1U3 AoS 2AchievableSection C style · new3 marks

A developer at a Victorian government agency copies a production database of citizens' personal details onto a personal laptop to continue working at home. Identify the relevant legislation and describe how it may have been breached.

6 ruled lines
Show response
Full-mark response

Legislation: Privacy and Data Protection Act 2014 (Vic).

The Act requires a Victorian public sector organisation to take reasonable steps to protect the personal information it holds from misuse, loss and unauthorised access. Copying a production database of citizens' personal details onto a personal, unmanaged laptop removes it from the agency's security controls, so the data could be accessed by anyone with access to that device or lost with it.

The agency could face an investigation by the regulator and fines, and would have to notify those affected.

Marking
  • 1Names the Act in full with year and jurisdiction.
  • 1States the obligation the Act imposes — protecting personal information from unauthorised access or loss.
  • 1Links the obligation to the specific action in the scenario.
Minimum full-mark answer

Privacy and Data Protection Act 2014 (Vic). It requires the agency to protect personal information from unauthorised access and loss. Copying the database onto a personal laptop takes it outside the agency's security controls, so it could be accessed by others or lost.

Students are not expected to know the dollar value of penalties — "fines" is sufficient.

Q11.2U4 AoS 2HardSection C style · new3 marks

A development team uses an AI assistant to generate large sections of a commercial product's code. No one reviews where the generated code originated. Discuss one ethical issue this raises for the organisation.

6 ruled lines
Show response
Full-mark response

The ethical issue is the use of intellectual property that belongs to someone else. Generated code may reproduce substantial parts of another developer's work, and by shipping it unreviewed the organisation is taking the benefit of that work without permission or attribution.

For the organisation this risks releasing a commercial product built on code it does not own, which could force a costly rewrite, and it damages the organisation's professional reputation with clients and with the developer community if it becomes known.

  • 1Names the ethical issue — intellectual property, or responsible use of AI during development.
  • 1Explains why it is an issue in this scenario.
  • 1States an impact on the organisation.

The issue is intellectual property. AI-generated code may reproduce another developer's work, and the team is using it in a commercial product without permission or attribution. The organisation could have to rewrite the product and would damage its reputation.

12

Validation techniques

~3 marks per paper U3 AoS 1 · U4 AoS 1
Key knowledge assessed
  • Existence checking · type checking · range checking

Only three techniques, and the examiners test whether students can apply the right one to the right field. Existence checking always comes first — there is no point checking the type or range of a value that was never entered. Common errors include describing an existence check as a lookup in a database, and applying a type check to a derived value the user never typed.

Q12.1U3 AoS 1AchievableSection C style · new3 marks

An enrolment form collects a student's year level, which must be between 7 and 12.

State the three validation checks that should be applied to this field, in the order they should run, and state one reason for that order.

6 ruled lines
Show response
Full-mark response

Existence check first, to confirm a value has been entered and the field is not blank. Then a type check, to confirm the value entered is an integer. Then a range check, to confirm the integer is between 7 and 12 inclusive.

The order matters because a type check or a range check performed on an empty field, or a range check on a value that is not a number, would cause an error rather than returning a result.

Marking
  • 1Existence, type and range checks all named, in that order.
  • 1Each check correctly described in the context of the year level field.
  • 1A reason for the order — later checks fail or error on an empty or non-numeric value.
Minimum full-mark answer

Existence check — a value has been entered. Type check — it is an integer. Range check — it is between 7 and 12. Existence must be first because checking the type or range of an empty field would cause an error.

UX characteristics and design principles

~3 marks per paper U3 AoS 2
Key knowledge assessed
  • UX characteristics — affordance, interoperability, security (authentication and data protection), usability
  • Design principles — alignment, balance, contrast, space, text formatting, usability, navigation

Usually attached to two supplied sketches, and almost always a Justify. The marks go to students who name the characteristic from the study design list and then point to the specific visible feature that demonstrates it. Answers that say one design is "cleaner" or "more user-friendly" earn nothing.

Q13.1U3 AoS 2HardAdapted from 2025 C Q84 marks

Two sketches of a parcel-tracking screen are proposed.

Sketch 1 shows a plain list of tracking numbers, a text box labelled "Enter action", and a Submit button. There is no sign-in indicator.

Sketch 2 shows the user's name and a logout button in the top right, a magnifying-glass search icon, and a drop-down list to choose a parcel.

For each sketch, justify which characteristic of user experience it better demonstrates compared with the other sketch.

4 ruled lines per sketch
Show response
Full-mark response

Sketch 1: Usability, in the narrow sense that the entire function sits on one uncluttered screen with a single input and a single action, so there is nothing for the user to interpret. Sketch 2 spreads the same task across a search icon and a drop-down, adding steps before the user can act.

Sketch 2: Security. It shows the signed-in user's name and a logout control, indicating the screen is behind authentication and that the session can be ended. Sketch 1 shows no sign-in state at all, suggesting parcel data is visible without the user being authenticated.

Marking
  • 1Names a UX characteristic from the study design for Sketch 1.
  • 1Supports it by pointing to a specific feature, and compares with Sketch 2.
  • 1Names a UX characteristic from the study design for Sketch 2.
  • 1Supports it by pointing to a specific feature, and compares with Sketch 1.
Minimum full-mark answer

Sketch 1: usability — one input and one button, so the task takes fewer steps than Sketch 2's search icon and drop-down.

Sketch 2: security — it shows the user's name and a logout button, so the screen is behind authentication, whereas Sketch 1 shows no sign-in at all.

Affordance would also be a valid choice for Sketch 2 — the magnifying glass is a universally recognised search symbol — provided the icon itself is named.
